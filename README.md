# Thai Open Transit

An open, structured, versioned and time-aware dataset of Thailand's rail
transit network, starting with Bangkok and its metropolitan region
(Nonthaburi, Samut Prakan, Pathum Thani).

**Live map (beta):** [thaiopentransit.vercel.app](https://thaiopentransit.vercel.app)

> Nobody in Thailand publishes the rail network as a structured, versioned,
> temporally-aware open dataset. The map is how we prove the dataset is good.

**The dataset is the product.** The web map in `apps/web` is a reference
implementation. If a change helps the map but hurts the dataset, the dataset
wins.

## What you get

### The dataset

| Entity   | Count | Source of truth               |
| -------- | ----- | ----------------------------- |
| Lines    | 10    | `data/source/lines/*.json`    |
| Stations | 192   | `data/source/stations/*.json` |
| Segments | 187   | `data/source/segments/*.json` |

Lines: Airport Rail Link, BTS Sukhumvit, BTS Silom, BTS Gold, MRT Blue,
MRT Purple, MRT Pink, MRT Yellow, SRT Dark Red, SRT Light Red.

What makes it different from a list of stations:

- **Time-aware.** Every station and segment carries `valid_from` / `valid_to`
  and a `milestones[]` history (`construction_started`, `trial_run`, `opened`,
  `extended`, `renamed`, `recoded`, `suspended`, `closed`). You can ask what the
  network looked like in any year.
- **Status is derived, never edited.** A station's status comes from its
  milestones, so it cannot drift out of sync with its history.
- **Stable IDs.** A station ID never changes, even when the operator renumbers
  its code. Old codes live in `code_history[]`.
- **Provenance on every fact.** Every entity carries `source_refs`. Data
  without a source fails validation.
- **Bilingual.** `name_th` and `name_en` on every user-facing entity.

### Downloads

Generated by `bun run data:build` and offered on the site's `/download` page.

| File              | Contents                                             |
| ----------------- | ---------------------------------------------------- |
| `network.json`    | Current-state lines, stations, segments (no history) |
| `network.geojson` | Station points and segment lines for GIS tools       |
| `stations.csv`    | Flat station table for spreadsheets                  |

### The web map

A static Next.js site on MapLibre GL with a self-hosted Protomaps basemap (no
third-party tile host).

- Lines styled by status: open, under construction, planned, suspended
- Station search in Thai, English, station ID and historical codes
- Station panel with names, lines, structure, accessibility, opened date and
  last verified date, plus a deep link (`?station=BL15`)
- Line groups with show / hide, station labels toggle, light and dark themes
- Year slider to watch the network grow over time
- My location and nearest open station (location never leaves the browser)
- English / Thai UI switch
- "Report an error" button that opens a prefilled GitHub issue

The full, current feature list lives in [docs/FEATURES.md](./docs/FEATURES.md).

## Build it locally

Requires [Bun](https://bun.sh). No environment variables are needed: cloning
and building works offline against the data committed in `data/source/`.

```sh
bun install          # install workspace dependencies
bun run data:build   # generate data/dist/ artifacts from data/source/
cd apps/web && bun run dev
```

`bun run data:build` must run before `bun run dev`: the site reads
`data/dist/network.json` and `network.geojson`, which are generated, not
committed. (`apps/web`'s `build` script runs `data:build` for you.)

### Commands

| Command                        | What it does                                                    |
| ------------------------------ | --------------------------------------------------------------- |
| `bun run lint`                 | Prettier check                                                  |
| `bun run typecheck`            | TypeScript across packages, apps and scripts                    |
| `bun run test`                 | Vitest                                                          |
| `bun run data:import`          | Fetch raw OSM data into `data/source/`                          |
| `bun run data:seed`            | Run the historical era seeds in dependency order                |
| `bun run data:build`           | Generate `data/dist/` artifacts                                 |
| `bun run data:validate`        | Schema, graph integrity, provenance, verified dates and budgets |
| `cd apps/web && bun run build` | Static export to `apps/web/out/`                                |

`data:validate` fails on an empty network by design. To test against an empty
`data/source/`, run `ALLOW_EMPTY=1 bun run data:validate`.

## How it works

```
data/source/ + data/overrides/          (structured JSON, reviewed via PR)
        |
        v
scripts/build   -- validated against packages/schema
        |
        v
data/dist/  network.json, network.geojson, stations.csv
        |
        v
apps/web  -- static export  -->  CDN
```

The public site never talks to a database. It survives outages, costs near
zero to host, and stays portable to any static host. The single exception is
an optional view counter in an isolated stats store
([ADR 0002](./docs/adr/0002-visit-counter.md)); the map works without it.

### Repository layout

| Path                     | Role                                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------- |
| `packages/schema`        | Zod schemas, TS types and generated JSON Schema. The single source of truth for entity shapes |
| `packages/network-graph` | Graph integrity, interchange resolution, temporal (`as_of`) queries                           |
| `packages/geo-utils`     | THAI-W75 to WGS84 reprojection, polyline tools, validators                                    |
| `packages/renderer`      | Data to SVG schematic generator (not yet wired into the site)                                 |
| `packages/ui`            | Shared UI components                                                                          |
| `apps/web`               | Public static site                                                                            |
| `scripts/import`         | OSM import and historical era seeds                                                           |
| `scripts/build`          | Artifact generation                                                                           |
| `scripts/validate`       | Schema, graph, provenance and date checks                                                     |
| `data/source`            | Raw imports, write-once                                                                       |
| `data/overrides`         | Manual corrections, one file per entity                                                       |
| `docs/adr`               | Architecture decision records                                                                 |

### CI

Every PR runs: Prettier, typecheck, Vitest, JSON Schema drift check, dataset
build, dataset validation, a `last_verified_at` bump check, web build and the
bundle size budget. The budget (CLAUDE.md section 7) fails the build if first
load exceeds 300 KB compressed or `network.json` exceeds 120 KB brotli.

## Roadmap

Full detail in [SPEC.md](./SPEC.md) section 4.

| Phase | Scope                                   | Status                                                                                                      |
| ----- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1     | Public read-only map + dataset download | Mostly shipped. Remaining: schematic mode, offline (PWA)                                                    |
| 2     | Time travel                             | Partial. Year slider shipped. Next: `?as_of=` permalinks, era presets, playback, era stats, plan vs reality |
| 3     | Admin plane                             | Not started. Invite-only editors, Postgres RLS, four-eyes review, append-only audit log                     |
| 4     | Wikipedia-style transparency            | Not started. Per-entity history, diffs, recent changes feed, contributor attribution                        |
| 5     | Expansion                               | Speculative. Route planner (idea), GTFS export, airport links, fares, public API, other Thai cities         |

The schema is already bitemporal and revision-shaped, so Phase 3 can land
without a data migration.

**Beyond Bangkok:** [ADR 0001](./docs/adr/0001-multi-region-and-multi-mode.md)
(Proposed) sketches how more regions, countries and transit modes fit in. New
cities are added as data, not as new brands. A custom domain is planned; until
then the site lives on Vercel.

**Non-goals:** real-time train positions, a production journey planner, ticketing, native
apps, anonymous crowd editing, monetisation.

## Contributing

Full guide: [CONTRIBUTING.md](./CONTRIBUTING.md). Security problems: see
[SECURITY.md](./docs/SECURITY.md).

- **Found wrong data?** Use the "Report an error" button on any station, or
  open an issue. Include a source.
- **Fixing data yourself:** put corrections in `data/overrides/`, never edit
  `data/source/`. Every change needs `source_refs`. Use the `data:` commit
  type and keep data changes out of code PRs.
- **Acceptable sources:** OpenStreetMap, MRTA / DRT / SRT published documents,
  or original work. Never copy, trace or adapt copyrighted transit maps.
- **Writing code:** read [CLAUDE.md](./CLAUDE.md) first. Its architectural
  rules are decisions, not suggestions. Ship a user-visible feature? Update
  [docs/FEATURES.md](./docs/FEATURES.md) in the same PR.
